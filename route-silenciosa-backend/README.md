# Ruta Silenciosa ingestion API

This directory defines the independent data layer used by the NoiseCapture fork.
It does not replace or modify the official Noise-Planet/OnoMap database.

## Endpoint expected by the Android client

`POST /v1/measurements`

Headers:

- `Content-Type: application/json`
- `Authorization: Bearer <token>` when an API key is configured
- `X-Client: NoiseCapture-RutaSilenciosa`

The endpoint should return any `2xx` status after storing the measurement.
Use idempotency based on `source`, `measurement.record_utc` and a client/device identifier generated by the project backend. Do not use the local SQLite record id as a globally unique key.

## Payload sections

- `measurement`: aggregate metadata for the recording
- `manual_tags`: labels supplied by the user
- `track`: GeoJSON points with LAeq and spectral bands
- `sound_classifications`: automatic or user-validated sound categories
- `audio_stored`: always `false`

## Android configuration

The client reads these SharedPreferences keys:

- `settings_route_silenciosa_enabled`: boolean
- `settings_route_silenciosa_url`: API base URL, for example `https://api.example.cl`
- `settings_route_silenciosa_api_key`: optional bearer token

Until a settings screen is added, they can be provisioned by a managed build, a debug configuration screen, or Android instrumentation during the pilot.

## Recommended deployment

- FastAPI or Cloud Run service
- PostgreSQL with PostGIS
- Secret Manager for API credentials
- HTTPS only
- request-size and rate limits
- no raw audio fields or object storage buckets

Apply `schema.sql` before starting the API.

## Classification integration

The Android side includes a JSONL sidecar store. A local YAMNet/MediaPipe engine should append one `SoundClassification` per inference window. This deliberately keeps classification data separate from NoiseCapture's existing SQLite schema and official export format.
